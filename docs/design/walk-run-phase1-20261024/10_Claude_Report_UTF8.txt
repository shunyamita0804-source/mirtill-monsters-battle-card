・エンジン：ゲームエンジンは使っていない。TypeScript＋ブラウザの DOM。人物は <div> に CSS の background-image（1枚の歩行シート）を
　貼り、background-position でコマを選び、transform: translate で位置を動かす。地図は <div> に絵と transform。Canvas・WebGL は不使用。
　ビルドは Vite 7、テストは Vitest。画面は 390×844 の論理px で組み、実機の画面に合わせて全体を拡大縮小（src/ui/stage.ts）
・投影：真上からの見下ろし 2D（GB版風の格子マップ。奥行きの縮みなし。人物は立ち絵として描く）。
　重なり順は足元の y（人物・家具とも）
・入力：画面のどこでも指をすべらせる仮想スティック（12px 動かすと開始、16px 未満は無効、45°ずつの8方向、境目の±8°は前の向きを保つ）。
　36px 以上倒すと走り、28px 未満に戻すと歩き。タップでその場所まで経路探索して歩く（人・家具をタップで話す／調べる）。
　パソコンは矢印キー（2つ同時で斜め）、Shift で走る
・移動方向数：8（マス目の上を1マスずつ。斜めは √2 マス＝縦横と同じ 論理px/秒。角のすり抜けなし）。セーブに残す向きは4（上下左右）
・画像方向数：8行（正面・背中・左・右・左下・右下・左上・右上）。右・右下・右上は 左・左下・左上 の左右反転（ツールで作る）
・表示サイズ（論理px。iPhone 13/14 系の 390pt 幅なら 1論理px≒1pt≒3画素）
　　街・部屋：1マス 18px（設計図 32 単位 × 0.5625）。人物のコマ 97.2px 高（横は主人公だけ 1.1 倍で 80.2px）。
　　　　　　　街は全体を 1.15 倍で見せるので画面では コマ 111.8px 高・92.2px 幅、絵の実際の高さ ≒98px（コマの 88%）

6. 不自然さの原因：根拠、再現手順、修正済み／素材待ち／未確認
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
（確認画面：?qa=1&lab=walk。再現手順は 8 章の操作で）

(a) 足滑り【確定・素材と数値の設計の不一致・未修正（ユーザーの判断待ち）】
　根拠：男性・左向きの8コマで、地面に着いている足の位置を計測（コマ 270×360 のシートの px）
　　　　着いた足（右足）の中心：コマ1 x=76 → コマ2 94 → コマ3 177 → コマ4 216（つま先でけり出し）→ 次の1歩が始まるコマ5では後ろの足 202
　　　　→ 絵の中で「着いた足が体に対して後ろへ動く量」は 1歩あたり約 126〜140px（コマの高さ 360 の 0.35〜0.39、絵の身長 317 の 0.40〜0.44）
　　　　ゲームの1歩は 0.58×360＝209px → 絵の足が動く量の約 1.6 倍。つまり足が地面を 1.6 倍の距離「すべって」進んでいる
　再現：確認画面「その場で・左・歩く・3倍」で地面線と足を見る。移動（カメラ固定）で格子と足を比べると、足が格子に対して前へすべる。
　　　　「再生速度 ×1.6」にすると足と地面が合う（そのかわり約 26コマ/秒でパタパタする）
　背景：2026-10-24 に「パタパタ速すぎる」で 0.45→0.58 にした結果、足滑りが増えた。歩く速さ（2.7 身長/秒＝実際の人の約3倍。
　　　　街を早く移動するためのユーザー選択）と「自然な歩幅」は両立しない。選択肢は 10 章と 12 章

(b) 走りが「速い歩き」【確定・素材待ち】走りの絵が無い（5 章）。コマ数の不足ではなく絵の不足

(c) 前の3ポーズの行（男性の斜め4方向・女性の全8方向）【確定・素材待ち】
　「足を運ぶ途中」が無く「立つ」で代用 → 1周に2回、足がそろって止まって見える。体の上下は絵に無く、プログラムの縮み 1.8% で補っている

(d) 男性・背中の後半4コマが合成【確定・素材待ち】上半身・腕が前半と同じなので腕が振れず、すそも揺れない

(e) 男性・左向きの奥・手前の足が入れ替わっていない【確定（引き継ぎメモの記録＋画像で上下段の形がほぼ同じ）・素材待ち】

(f) 右向きは左向きの反転【確定・素材待ち（右向きの絵が無い）】かばんの位置が向きで入れ替わる。勝手に反転を増やしてはいない（今回は変更なし）

(g) 走りに切り替えるとコマが飛ぶ／戻る【確定・修正済み】
　根拠：前のコード（worldScreen.ts）は「歩いた総距離 ÷ いまの歩幅」でコマを決めていたため、歩幅が 56.4→58.3 に変わる瞬間に
　　　　同じ距離でもコマ番号が変わっていた（例：距離 100px で 7→6 に戻る）。
　修正：位相（歩数）を積み上げる形に（walkAnim.ts の advancePhase）。テスト「歩幅が変わる瞬間に位相が変わらない」

(h) 切り出し・基準点のばらつき【確定・問題なし】全コマで足のいちばん下は y=339〜341。横は上半身の中心をそろえる道具で合わせてある。
　第2版の行で頭の高さが変わるのは体重の上下（意図どおり）

(i) 毎更新で先頭から再生【確定・問題なし】コマは位相から決め、1歩の途中で作り直さない。止まったときだけ 0 に戻す（次は右足が着くコマから）

(j) 端末の描画頻度で速さが変わる【確定・問題なし】経過時間（上限 50ms）で進める。テストで 60/30/20fps の2秒間の距離差 < 1マス

(k) 斜めの速さ増加【確定・問題なし】斜めは √2 マスを同じ 論理px/秒 で進む（テストで縦横と同じ距離）

(l) カメラと人物の移動の区別【確定・問題なし】カメラは別の値（遊び 14/18px・遅れて追う・先読み）。確認画面の「カメラ固定」で人物だけが動くのを確認

(m) 壁での足踏み・ちらつき【確定・問題なし】進めないと1歩を始めないので距離も位相も進まず、90ms 後に立ち止まり。確認画面で柱に当てて確認
　（向きを変えるのは同じ向きを 0.22 秒押し続けたときだけ）

(n) iPhone 実機でのコマ飛び・読み込み【未確認】この環境は Chromium のみ

・操作
　人物：男性／女性　　場所：街と同じ（マス 18px・人物 97.2px）／ダンジョンと同じ（マス 40px・人物 54px）
　向き：8つ　　状態：停止／歩く／走る（「その場で」のとき）

　　　　　移動のときは、画面をなぞる・矢印キーで歩く。大きく倒す・Shift で走る。状態・向きは操作に従う

　既定に戻す／位置を戻す／格子・地面線・基準点：あり／なし
・ここで変えた値は保存しない（セーブも設定も、メモリの中の仮のものを使う）。本編のセーブは触らない

10. 次に描く男性1方向の素材仕様（セル寸法・原点・余白・向き・順序・周期案）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
詳しくは同じフォルダの 20_Spec_male_left_walk_run_UTF8.txt（画像AIに渡せる形）。要点：
・先行する向き：左向き（横）。理由：足の運び・接地・歩幅が見えるのは横向きだけで、足滑りの判定も横でしかできない。
　いまの左向きは奥・手前の足が入れ替わっていない問題もある。投影（真上見下ろしの立ち絵）と方向設計（右は左の反転）にも合う
・1枚に8ポーズ：横長 1536×1024 PNG、2段×4列、1ポーズの枠 384×512。上の段＝奥の右足の1歩、下の段＝手前の左足の1歩
　（今回の redo8 と同じ形。1歩ずつ別の絵にすると2枚目が同じ絵になりやすかったため）
・共通の座標：枠の横の真ん中（x=192）に体の中心、足元の線 y=428、頭の上 y≈97（身長 約331px）。全ポーズ同じ倍率・同じ原点で描く。
　自動トリミング・コマごとの拡大縮小・中央寄せは禁止。体の上下（2・6 がいちばん低く、4・8 がいちばん高い。差は身長の 2〜3%）は絵に残す
・余白：枠の左右 12px 以上は空ける（はみ出し・となりとの重なり禁止）。文字・番号・枠線・影・地面は描かない。背景は透明
・ゲームでの扱い：Claude が 384×512 → 270×360 のコマ（足元 (135,338)・身長 317px）に縮め、ゲームのシートの行 2（左）に入れる。
　右向きは反転（かばんが反対側になる。右向きの専用の絵を描くなら別途）
・歩き8コマの順序：1 着く（右足）→2 沈む→3 足を運ぶ→4 伸び上がる→5 着く（左足）→6 沈む→7 足を運ぶ→8 伸び上がる。
　「両脚を広げたポーズ」だけを連ねない。腕は足と反対に振る
・歩幅（いちばん大事。ユーザーが選ぶ）：
　　A案（自然な歩幅）：コマ 1・5 で前の足のかかと〜後ろの足のかかと ≒ 身長の 0.45（枠では約 150px）。
　　　→ ゲームの1歩の設定（STEP_PER_HEIGHT 0.58）を絵に合わせて 0.40 前後にする必要がある（歩き 231px/秒だと 約5.9歩/秒・24コマ/秒。
　　　　 8コマの絵なら「パタパタ」ではなく「速足」に見える見込み。歩く速さを落とすなら歩数も減る）
　　B案（いまの速さに合わせた大股）：かかと〜かかと ≒ 身長の 0.66（枠では約 218px）。ゲームの設定は変えずに足滑りがなくなるが、
　　　早歩き・大股に見える
　　C案（いまのまま）：歩幅は描き手まかせ、足滑りは残る
　　Claude のおすすめ：A案＋走りの絵（速い移動は走りに任せる）。ただし数値の変更はユーザーの承認が要る
・走り8コマ（別の動作として）：1 着地（前傾・ひざ曲げ）→2 沈む→3 けり出し→4 浮く（両足が地面から離れる）→5〜8 反対の足で同じ。
　かかと〜かかと ≒ 身長の 0.9〜1.0（走りの速さ 393px/秒で 約4.4歩/秒・18コマ/秒）
・保存名：player_male_left_walk8.png（歩き）、player_male_left_run8.png（走り）
・既存実装上の制約：
　　- 1歩4コマ・1周8コマは実装の前提（FRAMES_PER_STEP＝4・WALK_COLS＝8）。6コマ・12コマにするなら walkAnim.ts の定数を変える（可能）
　　- 走りの絵を入れるにはシートに列か行を足す（いまは 9列×8行）。別ファイルに分けると iPhone で読み込み直しの間に人物が消えた前例があるので、
　　　同じ1枚に行を足す形（2430×5760）を予定。大きさが iPhone で問題ないかは実機確認が要る
　　- 右向きは反転で作る前提（右向きの専用の絵を描くなら、ツールと行の扱いを変える）
