## 2. 実装した機能

### A. スマホ画面基盤

- 論理解像度 390×844（縦）のステージを、セーフエリアを除いた表示領域に合わせて拡大縮小（`src/core/stageLayout.ts`、`src/ui/stage.ts`）
- 基準の 390×844 は常に全部が見える。縦長の端末では論理高さを伸ばして余白をなくし、横長の画面では左右に余白を作って中央に表示
- iPhone のセーフエリアに対応（`viewport-fit=cover` と `env(safe-area-inset-*)`）
- 操作はタップのみ。ダブルタップ拡大・長押しメニュー・テキスト選択は抑止し、ボタンの高さは 40px 以上

### B. 画面遷移（4画面）

| 画面 | 内容 |
| --- | --- |
| タイトル | 仮のビジュアルと「はじめる」ボタン（→ 街） |
| 街 | 仮の街マップと施設一覧（カードショップ／カードバトル）。「タイトル」で戻る |
| カードショップ | 仮カード12枚の一覧。タップで詳細表示。「街へ」で戻る |
| カードバトル | バトル画面の基盤（下記）。「街へ」で戻る |

- 画面ID一覧（`src/config/screens.ts`）、画面定義の登録表（`src/ui/screens/registry.ts`）、`Router` の3つで構成
- ダンジョン・ガチャ・大会は、画面IDと画面定義を追加するだけで足せる構造（手順は `docs/architecture.md`）

### C. カードバトル画面の基盤

| 項目 | 内容 |
| --- | --- |
| 対戦相手のカード表示領域 | 場3枠（1枠は空き）、裏向きの手札と枚数、マナ |
| プレイヤーのカード表示領域 | 場3枠、マナ |
| 手札表示領域 | 横スクロールの手札（5枚） |
| マナ表示領域 | 丸の数と数値（例 3/5） |
| カード選択・詳細確認 | 1回タップで選択（枠が光り、下部に場所と名前を表示）。もう一度タップするか「詳細」ボタンで詳細を表示。閉じるボタンか背景タップで閉じる。相手の手札は選択不可 |
| 仮のターン切り替え | 「ターン終了」→ 相手のターン（仮）→「相手ターン終了（仮）」→ あなたのターン。ターン数が進み、選択は解除される |

- 状態の変更はすべて `battleReducer`（`src/game/battle/battleState.ts`、DOM 非依存）を通す

### 設計ルールへの対応

- **UI とロジックの分離**：`src/core/` と `src/game/` は DOM を使わない純粋な TypeScript で、Vitest でテストしている。UI は `src/ui/` だけ
- **正式素材への差し替え**：`assets/images/cards/` に画像を置き、カード定義に `art` を指定するだけで表示に使われる（`import.meta.glob` で自動的に一覧化）。画像がなければ仮の絵で表示する
- **技カードの外部画像**：`layout: 'full'` を指定すると、画像をカード全面に表示する（完成済みのカード画像向け）
- **仮データの明示**：仮カードはすべて `isPlaceholder: true`、IDは `tmp-` 始まり、名前は「仮」始まり。画面上にも「仮」の表示がある
